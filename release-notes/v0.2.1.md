# AR-Infra CLI v0.2.1

**Release Date:** July 5, 2026
**Status:** Stable
**Distribution:** PyPI, GitHub Releases (Binary)

## Overview

This release moves feature-to-file mapping out of Python source code and into a YAML configuration file. Template file names, directories, environment variables and dependencies for each infrastructure feature are now declared in `feature-conf.yml` and loaded at runtime through a typed schema. No functional change for end users, this is an internal maintainability fix.

## What's New in v0.2.1

### YAML-Driven Feature Configuration

- **`feature-conf.yml` as single source of truth**: shared and specific directories, files, env variables and dependencies for every `TemplateFeature` are now declared in YAML instead of hardcoded Python dictionaries.
- **Typed loading**: `YamlFileProcessor` deserializes the file into `FeatureConfigSchema` / `FeatureSchema`, so a malformed config fails fast at load time instead of silently producing a wrong project layout.
- **Placeholder resolution kept in code**: `src_package` and `test_package` are still resolved through `{src_package}` / `{test_package}` placeholders in `_resolve` / `_resolve_list`, so the YAML stays free of duplicated path prefixes.
- **Cached load**: `_load_config` is decorated with `functools.cache`, so the YAML is parsed once per process regardless of how many times `FEATURE_FILES` or `FEATURE_DEPENDENCIES` are consulted.
- **Frozen binary support preserved**: the loader still branches on `sys.frozen` to resolve the config path from `sys._MEIPASS` when running as a PyInstaller binary, matching the existing packaging setup.

### Why This Change

Renaming a template file, for example `RabbitConfig.java` to `RabbitConf.java`, previously required editing `feature_files.py` and cutting a new CLI release for a change that has nothing to do with CLI logic. From this version on, the same rename only requires updating `feature-conf.yml`. A new binary still needs to be built and released, since the YAML is bundled as a packaged resource, but the Python code itself does not change for this class of update.

## Installation

### Binary Installation (Recommended)

#### Linux (x64)

```bash
curl -LO https://github.com/Abega1642/ar-infra-cli/releases/download/v0.2.1/ar-infra-linux-amd64

shasum -a 256 -c ar-infra-linux-amd64.sha256
chmod +x ar-infra-linux-amd64
sudo mv ar-infra-linux-amd64 /usr/local/bin/ar-infra
```

## Usage

Usage is unchanged from v0.2.0. See `ar-infra init --help` and `ar-infra add-dependency --help` for the full command reference.

## Migration from v0.2.0

This is a non-breaking, backward-compatible release.

**Key points:**

1. No CLI flag, command, or generated project structure changes for end users.
2. `TemplateFeature` enum values are unchanged, `feature-conf.yml` keys map to the same enum names as before.
3. Projects generated with v0.2.0 continue to work without modification.
4. Contributors maintaining the template repository should edit `feature-conf.yml` instead of `feature_files.py` for any file, directory, env variable, or dependency change per feature.

**Recommended migration path:**

1. Update to v0.2.1 to benefit from the simplified configuration workflow.
2. If you maintain a fork, port any local edits from `feature_files.py` into the equivalent `feature-conf.yml` entries before rebasing.

## Security Considerations

- Binary integrity verification via SHA256 checksums is strongly recommended.
- All binaries are built via GitHub Actions with full transparency.
- `feature-conf.yml` is loaded through a typed schema (`FeatureConfigSchema`), rejecting unexpected structure rather than trusting raw YAML at runtime.
- The config file is a packaged resource shipped with the CLI, it is not fetched from a remote source at runtime, so this change does not introduce a new network-facing attack surface.
- Secrets are injected at build time rather than bundled, improving security.
- Source code is available for audit at [https://github.com/Abega1642/ar-infra-cli](https://github.com/Abega1642/ar-infra-cli)

## System Requirements

**Binary Distribution:**

- Linux: x86_64 architecture, GLIBC 2.17+
- macOS: 10.13+ (Intel), 11.0+ (Apple Silicon)
- Windows: Windows 10/11, x86_64 architecture

**Python Package:**

- Python 3.11 or higher
- pip or pipx package manager

## Known Limitations

- `feature-conf.yml` is bundled at build time, editing it still requires cutting a new CLI release for the change to reach users, only the source-code touch point was removed.
- Only PostgreSQL and MySQL are supported as relational databases in this release.
- The S3-compatible bucket used is [BackBlaze](https://www.backblaze.com).
